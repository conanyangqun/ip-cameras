# 人形检测误报优化方案分析

## 背景

当前使用 OpenCV HOG+SVM 行人检测器，假阳性较高，常见误报来源：

- 树叶、光影、水面等杂乱纹理
- 背景中类人形轮廓（椅子、衣架、立杆等）

以下方案按资源占用从低到高排列，方案之间可叠加使用。

## 方案 1：MOG2 背景建模门控 + 现有 HOG（几乎零成本）

用 `cv2.createBackgroundSubtractorMOG2()` 常驻内存维护背景模型，每帧先计算前景占比，只有前景比例超过阈值时才运行 HOG 检测。

### 原理

静态背景中的误报（树影晃动处的杂乱纹理、固定家具）前景占比≈0，直接跳过 HOG，从源头消除这类误报。

### 资源

- 极低：MOG2 是经典 CPU 算法，比 HOG 本身快得多
- 当前程序每帧单独起 ffmpeg 抓图，背景模型只需在摄像头线程内保持状态，即可跨抓拍周期工作

### 实现要点

- 背景模型对象需挂在摄像头线程内（`process_camera` 局部变量或传参），每个摄像头独立维护，不能做成全局（多摄像头场景会互相污染）
- 保存/告警逻辑不受影响，只是检测前加一道门槛：

```python
前景掩码 = 背景模型应用(帧)
前景占比 = 非零像素 / 总像素
若 前景占比 < 阈值(如 0.01~0.02) → 跳过 HOG，视为无运动
否则 → 正常 HOG 检测
```

### 参数与坑

| 问题 | 对策 |
|---|---|
| 光线剧变（日出日落、开关灯）导致整帧被判为前景 | MOG2 自带学习率会自动适应，可额外设"前景占比 > 0.6 时判定为异常帧并重置模型" |
| 镜头轻微抖动/自动曝光产生整帧噪声 | 开启 `detectShadows=True` 并在计数前剔除阴影灰度值（127） |
| 阈值敏感 | 建议做成 `cameras.json` 可配置项（如 `fg_threshold`），默认保守值 |

### 局限

- 对"背景里本来就有的类人物体被误检"无效（该类前景一直存在）
- 离线批量检测（`detect_humans_in_folder`）没有时序上下文，无法使用背景模型

## 方案 2：轻量深度学习检测器（效果最好）

用 YOLOv8n / YOLO11n（nano 版，权重仅 ~6MB）导出 ONNX，用 `cv2.dnn` 推理。

### 优势

- **不需要 PyTorch**，运行时只依赖已有的 opencv-python + numpy，导出后推理完全离线
- 只取 `person` 类别 + 置信度阈值，误报显著低于 HOG，漏检也更少
- 对实时抓拍和离线批量检测两条链路都生效

### 实现要点

- 权重：`yolov8n.pt` → `yolo export format=onnx imgsz=416`（导出需临时装一次 ultralytics，运行时不依赖）
- 推理：`cv2.dnn.readNetFromONNX`，后处理解析 84×8400 张量中 `person`（类别 0）的行，NMS 可复用现有 `non_max_suppression`
- 输入尺寸建议 416 或 320；远距离小目标场景可保持 640

### 资源量级参考（现代 x86 CPU，单线程近似）

| 检测器 | 1080p 单帧耗时 | 内存增量 |
|---|---|---|
| HOG（现状） | ~1-2s | ~0 |
| HOG + MOG2 门控 | 大部分周期 <50ms，仅前景时跑 HOG | +几 MB |
| YOLOv8n ONNX @416 | ~150-400ms | +50MB 左右 |
| YOLOv8n + OpenVINO 后端 | ~60-150ms | +200MB |

## 方案 3：时序确认（配合任何检测器，零成本）

连续 N 个检测周期（如 2~3 次 `capture_cycle`）都检测到人形，才保存标注图/发送告警。

- 当前程序"每几秒抓一帧"的架构天然适合
- 偶发性单帧噪声误报几乎全部被过滤
- 代价：告警延迟增加几秒（N=2 时约 6 秒）
- 在 `process_camera` 里维护 `consecutive_motion` 计数器即可，与方案 1/2 完全正交

## 综合建议

优先级：**方案 3 → 方案 1 → 方案 2**。

1. 方案 3 最简单，先叠加时序确认
2. 方案 1 消除静态背景类误报，两者合计改动约 30 行、零新依赖，通常能把误报压下一个数量级
3. 实测后若小目标漏检或复杂场景仍不理想，再上方案 2
